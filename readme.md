# Многопоточный парсер курсов валют — вариант 4

Spring Boot MVC приложение на Java 17. Получает официальные курсы ЦБ РФ для **USD, EUR, CNY, GBP, JPY**, считает изменение к предыдущему календарному дню и сохраняет результат во встроенную файловую H2. Все курсы выражены в **рублях за одну единицу валюты**, включая JPY, для которой ЦБ может указывать номинал 100.

**[Скачать готовый архив для запуска](https://github.com/che1nov/currency-parser/releases/latest/download/currency-parser.zip)** · [Релизы](https://github.com/che1nov/currency-parser/releases)

## Запуск для преподавателя

Нужна **Java 17 или новее**, свободный порт **8080** и доступ к `https://www.cbr.ru`. Установка БД, регистрация, ключи API и изменение конфигурации не требуются.

**Из готового архива `currency-parser.zip`:** распакуйте его и запустите `start.bat` в Windows либо `sh start.sh` в macOS/Linux. Скрипт запускает приложенный JAR. Терминал должен оставаться открытым.

Можно также выполнить в папке распакованного проекта:

```sh
java -jar currency-parser.jar
```

**Из исходников:** откройте именно `currency-parser/pom.xml` как Maven-проект, выберите JDK 17 и нажмите Run у `ru.study.rates.CurrencyParserApplication`. Maven загрузит зависимости при первом открытии. Внешний родительский проект содержит прошлые домашние задания и не запускает этот сервис.

Альтернативно, при установленном Maven 3.6.3+ выполните в папке `currency-parser`:

```sh
mvn clean verify
java -jar target/currency-parser-1.0.0.jar
```

Через секунду после запуска начинается автоматический сбор за сегодня, затем он повторяется через час после завершения предыдущего запуска. Дата «сегодня» определяется по `Europe/Moscow`. Сбор обычно занимает несколько секунд; предельное ожидание сетевых задач — 15 секунд. Для остановки нажмите Ctrl+C.

## Последовательность проверки

### 1. Проверить автосбор

Откройте в браузере или выполните:

```sh
curl "http://localhost:8080/api/status"
```

Дождитесь `"state":"SUCCEEDED"` и `"savedCount":5`. Пока идёт сбор, возвращается `RUNNING`. Состояние `FAILED` содержит поле `error`: например, сайт ЦБ недоступен. Приложение при этом продолжает работать.

```sh
curl "http://localhost:8080/answer"
```

Ожидается массив из пяти валют за сегодня. До первого успешного сбора массив пустой.

### 2. Запустить сбор вручную

**POST `http://localhost:8080/api/collect`**, заголовок `Content-Type: application/json`, тело:

```json
{}
```

```sh
curl -X POST "http://localhost:8080/api/collect" \
  -H "Content-Type: application/json" \
  -d '{}'
```

Запрос синхронный: HTTP 200 приходит после записи в H2. Ответ содержит `state`, `date`, `savedCount`, `sourceUrl` и массив `rates`. Если запрос пересёкся с другим сбором, придёт HTTP 409; дождитесь его завершения и повторите запрос.

### 3. Собрать историческую дату по входной ссылке

**POST `http://localhost:8080/api/collect`** с телом:

```json
{
  "sourceUrl": "https://www.cbr.ru/currency_base/daily/",
  "date": "2024-03-05"
}
```

```sh
curl -X POST "http://localhost:8080/api/collect" \
  -H "Content-Type: application/json" \
  -d '{"sourceUrl":"https://www.cbr.ru/currency_base/daily/","date":"2024-03-05"}'
```

Допустима также ссылка `https://www.cbr.ru/scripts/XML_daily.asp` (для обеих ссылок разрешён хост без `www`). Параметр `date` передаётся отдельно. Если поля не указаны, используются источник ЦБ и сегодняшняя дата. Другие сайты и произвольные URL не поддерживаются. Входная ссылка выбирает источник; парсер обращается к его официальному XML-представлению, а не к HTML-разметке.

### 4. Получить конкретную валюту на конкретную дату

**GET `http://localhost:8080/answer?date=2024-03-05&currency=USD`**

```sh
curl "http://localhost:8080/answer?date=2024-03-05&currency=USD"
```

Ожидается массив с одной записью USD. Код валюты нечувствителен к регистру. Если дата ещё не собиралась, возвращается `[]`; GET только читает H2 и не запускает сетевые запросы. Сначала выполните POST из шага 3.

Поля записи:

| Поле | Значение |
|---|---|
| `date` | Дата, на которую запрошен курс |
| `currency`, `name` | Код и название валюты |
| `baseCurrency` | Всегда `RUB` |
| `effectiveDate` | Дата действующего курса из XML ЦБ |
| `previousEffectiveDate` | Дата действующего курса для предыдущего календарного дня |
| `rate` | Рубли за одну единицу валюты на `date` |
| `previousRate` | Рубли за единицу на `date - 1 день` |
| `change` | `rate - previousRate`, в рублях |
| `changePercent` | `(rate - previousRate) / previousRate * 100` |
| `fetchedAt` | Момент получения в UTC |

ЦБ не устанавливает новый курс каждый календарный день. Поэтому `effectiveDate` может быть раньше `date`. Если на оба дня действует один курс, изменение равно нулю. Это сравнение календарных дней, а не двух последних публикаций ЦБ. Официальный курс ЦБ также не является внутридневной биржевой котировкой.

Расчёт ведётся в `BigDecimal`: курс округляется до 10 знаков, процент — до 6, правило `HALF_UP`.

### 5. Проверить сортировку

**GET `http://localhost:8080/answer?date=2024-03-05&sort=rate&direction=desc`**

```sh
curl "http://localhost:8080/answer?date=2024-03-05&sort=rate&direction=desc"
curl "http://localhost:8080/answer?date=2024-03-05&sort=changePercent&direction=asc"
curl "http://localhost:8080/api/currencies"
```

`sort`: `currency` (по умолчанию), `name`, `rate`, `change`, `changePercent`.

`direction`: `asc` (по умолчанию) или `desc`. При равных значениях порядок определяется кодом валюты по возрастанию. На одну дату максимум пять записей, поэтому пагинация не нужна.

### 6. Проверить повторный сбор и сохранность

Повторите POST для `2024-03-05`. GET за эту дату по-прежнему вернёт пять записей: составной первичный ключ `(requested_date, currency)` и `MERGE` предотвращают дубли. Затем остановите приложение и запустите снова **из той же папки**. Исторические курсы останутся доступны.

H2 автоматически создаёт `data/currency-rates.mv.db` относительно рабочей папки процесса. В архив БД не включена. При смене рабочей папки будет создана другая БД. Состояние последнего запуска `/api/status` хранится в памяти и после перезапуска начинается с `IDLE`; сами курсы сохраняются на диске.

### 7. Проверить ошибки

```sh
curl -i "http://localhost:8080/answer?currency=BTC"
curl -i "http://localhost:8080/answer?sort=unknown"
curl -i -X POST "http://localhost:8080/api/collect" \
  -H "Content-Type: application/json" -d '{"date":"not-a-date"}'
```

| HTTP | Ситуация |
|---|---|
| 200 | Сбор завершён или данные прочитаны; отсутствие записей представлено `[]` |
| 400 | Некорректный JSON, дата, валюта, URL, сортировка или неизвестное поле JSON |
| 409 | Другой сбор уже выполняется |
| 502 | Ошибка сети, тайм-аут или некорректный ответ ЦБ |
| 503 | Ошибка доступа к H2 |

Ошибки имеют формат `application/problem+json` с полями `status`, `title`, `detail`. Диапазон дат: от `2000-01-02` до сегодняшней даты по Москве. Ранее могут отсутствовать данные для выбранного набора валют; тогда сервис вернёт 502 без частичной записи.

Без интернета доступны уже сохранённые результаты. В свежей БД результатов нет; тестовые курсы не выдаются за реальные. Для проверки вычислений без сети служат автоматические тесты с явно заданными ответами источника.

## Архитектура и многопоточность

Использовано простое разделение **controller → service → repository / HTTP adapter**. Один источник, одна таблица, без лишних интерфейсов, ORM, CQRS и микросервисов.

```text
src/main/java/ru/study/rates/
├── CurrencyParserApplication.java  # Запуск и автоматическая сборка зависимостей Spring
├── web/                           # Контроллер, DTO и преобразование ошибок в HTTP
├── service/                       # Сбор, вычисление изменения, фильтрация и сортировка
├── adapter/                       # RestTemplate, разбор XML и нормализация номинала
├── repository/                    # JdbcTemplate, SQL для H2
├── model/                         # Неизменяемые записи и поддерживаемые валюты
└── config/                        # ExecutorService, HTTP-клиент, часы, расписание
```

| Требование задания | Реализация |
|---|---|
| Spring Boot MVC | `spring-boot-starter-web`, `RateController`, JSON DTO |
| Собственный ExecutorService | `ThreadPoolExecutor`: 4 именованных потока `cbr-worker-*`, `ArrayBlockingQueue` на 8 задач, `AbortPolicy` |
| Реальная параллельная работа | Два независимых HTTP-запроса за D и D−1 запускаются до ожидания результатов |
| Расписание | `@Scheduled`: первый запуск через 1 секунду, затем фиксированная задержка 1 час |
| H2 | Файловая БД, схема создаётся автоматически из `schema.sql` |
| Получение результатов | `GET /answer`, фильтр даты и валюты, сортировка |
| Parallel Stream API | Чтение снимка из H2 через JDBC, затем `parallelStream().filter().sorted().toList()` |
| Межсервисное взаимодействие | `RestTemplate` с JDK HTTP-клиентом обращается к официальному XML-сервису ЦБ |
| Потокобезопасные структуры | `ArrayBlockingQueue`, `AtomicReference<CollectionStatus>`, immutable records и `Map.copyOf` |
| Конкурентный доступ | `ReentrantLock.tryLock()` исключает пересечение ручного и планового сбора |
| Атомарность | `TransactionTemplate` в сервисе записывает все пять валют одной транзакцией |
| Завершение | Spring вызывает `shutdown()` пула; HTTP-запросы ограничены тайм-аутами, незавершённые Future отменяются |

Контроллер не считает курсы и не обращается к БД. Адаптер преобразует XML-поля `Nominal`/`Value` в рубли за единицу, не передавая внешние DTO сервису. Сервис считает абсолютное и процентное изменение. JDBC извлекает записи одним запросом; соединение и ResultSet не передаются в параллельные потоки.

Сбор ограничен одним активным запуском на экземпляр приложения. Это достаточная модель для учебного сервиса; очередь пользовательских заданий и несколько экземпляров не предусмотрены. Сетевые задачи выполняются в собственном пуле, `parallelStream` использует общий `ForkJoinPool`. Для пяти элементов параллельная сортировка не даёт практического выигрыша и добавлена для демонстрации требования задания.

Тайм-аут соединения — 5 секунд, HTTP-запроса — 10 секунд, суммарного ожидания пары задач — 15 секунд. При ошибке одного источника/дня пакет не записывается. Незавершённые задачи отменяются, блокировка освобождается, расписание продолжает работать. Во время сбора GET может читать последний полностью сохранённый результат.

XML ограничен 2 МиБ, DTD и внешние сущности отключены. Разрешён только известный источник; пользовательский URL не используется как произвольный сетевой адрес, перенаправления отключены. Логи Spring/SLF4J содержат время, имя потока и дату запроса.

Для совместимости с JDK 17 в HTTP-клиент добавлен публичный корневой сертификат HARICA TLS RSA Root CA 2021: на момент проверки его использует сайт ЦБ, но он отсутствует в некоторых сборках Java. SHA-256 сверен с [записью CA в Mozilla/CCADB](https://ccadb.my.salesforce-sites.com/mozilla/PrintViewForCase?CaseNumber=00000730); происхождение указано в `src/main/resources/certs/README.txt`. Стандартные доверенные CA сохраняются, проверки цепочки и имени хоста включены; системное хранилище Java не изменяется.

Официальное описание XML-сервиса: [документация ЦБ](https://www.cbr.ru/development/SXML/).

## Тесты и дополнительные настройки

```sh
mvn test
```

Тесты не обращаются к интернету: адаптер проверяется через `MockRestServiceServer`, приложение — через `MockMvc` с настоящей H2 в памяти и подменой клиента ЦБ. Проверяются кодировка Windows-1251, номинал JPY, выходные, HTTP-ошибки, некорректный XML, ограничения URL, вычисления, фильтрация, сортировка, отсутствие дублей, откат транзакции, одновременный запуск двух сетевых задач, HTTP 409 и прерывание задач.

Результаты проверки: [verification.md](verification.md). Дополнительно можно выполнить сквозную проверку с реальным ЦБ, если установлен Python 3:

```sh
python3 scripts/smoke_check.py
```

Она запускает собранный JAR на порту 18080 с временной БД, проверяет автосбор, историческую дату, расчёты, API и сохранность данных после перезапуска. Затем останавливает оба процесса и удаляет только свою временную папку. Основная БД приложения не затрагивается.

Параметры ниже необязательны и нужны только для экспериментов:

```sh
# Наблюдать несколько автоматических сборов с интервалом 10 секунд:
java -jar currency-parser.jar --collector.interval-ms=10000

# Отключить автоматический сбор, оставив ручной POST:
java -jar currency-parser.jar --collector.scheduling-enabled=false

# Если порт 8080 занят:
java -jar currency-parser.jar --server.port=8081
```

В исходном проекте замените `currency-parser.jar` на `target/currency-parser-1.0.0.jar`.
